# 성수 콘텐츠 관리 화면 정의서

2026-10-24

PRD의 "화면 목록과 역할"을 실제 구현 가능한 수준으로 구체화한 문서다. 문구와 에러 메시지는 초안이며 구현 중 다듬을 수 있다.

## 1. 장소 목록

- 데이터 소스: mock ([백엔드 API 가정 명세서](./backend-api-assumptions.md)의 `GET /admin/places` 응답 구조에 맞춤)
- 구성 요소
  - 상단 타입 필터: 전체 / 카페 / 맛집 / 팝업
  - 이름 검색 입력
  - 목록: 썸네일, 이름, 타입, 역/거리, 등록일
  - 화면 우측 상단 "장소 등록" 버튼 → 등록 폼으로 이동
  - 각 행의 "수정", "삭제" 액션
- 빈 상태: "등록된 장소가 없습니다. 장소를 등록해보세요." + 등록 버튼
- 에러 상태: 공통 폴백 메시지("요청을 처리할 수 없습니다. 잠시 후 다시 시도해주세요.")

## 2. 등록/수정 폼

| 필드 | 입력 방식 | 필수 | 검증/에러 메시지 |
| --- | --- | --- | --- |
| 장소 종류 | 선택(카페/맛집/팝업) | 필수 | 수정 화면에서는 비활성화 — "장소 종류는 등록 후 바꿀 수 없습니다. 바꾸려면 삭제 후 새로 등록해주세요." |
| 이름 | 텍스트 | 필수 | "이름을 입력해주세요" / "이름은 50자 이하로 입력해주세요" |
| 영문 이름 | 텍스트 | 선택 | 최대 100자 |
| 주소 | 텍스트 직접 입력 | 필수 | "주소를 입력해주세요" |
| 영문 주소 | 텍스트 | 선택 | 최대 510자 |
| 위도 / 경도 | 숫자 입력 | 필수 | "위도는 -90~90, 경도는 -180~180 사이로 입력해주세요" |
| 가까운 역 | 텍스트 | 필수 | 최대 100자 |
| 영문 역명 | 텍스트 | 선택 | 최대 200자 |
| 역과의 거리(m) | 숫자 입력 | 필수 | 0 이상 정수 |
| 요일별 영업시간 | 요일 7개 × (휴무 토글 + 시작/종료 시간, 브레이크타임 추가 가능) | 필수 | 휴무가 아닌 요일마다 영업시간 1개 이상 필요 — "모든 요일의 영업시간을 입력해주세요" |
| 팝업 운영 기간 | 시작일/종료일 | 장소 종류가 팝업일 때만 노출 및 필수 | "종료일은 시작일과 같거나 이후여야 합니다" |
| 썸네일 | 파일 첨부(이미지) | 등록 시 필수, 수정 시 선택 | 수정에서 생략하면 기존 썸네일 유지 |

- 저장 버튼 라벨: 등록 화면 "등록하기" / 수정 화면 "수정하기"
- 저장 성공: 목록으로 이동 + "장소가 등록되었습니다" / "장소가 수정되었습니다" 토스트
- 저장 실패(알려진 코드): PRD의 에러 코드별 메시지 적용
- 저장 실패(그 외): 공통 폴백 메시지
- 수정 화면 진입 시 기존 값(영문 필드 포함)을 모두 채워서 보여주고, 저장 시에도 항상 전체 값을 함께 전송한다 (PUT이 전체 교체이기 때문).

## 3. 삭제 확인

- 모달 문구: "'{장소명}'을 삭제하시겠습니까?"
- 버튼: "취소" / "삭제"
- 성공: 목록에서 제거 + "삭제되었습니다" 토스트
- 이미 삭제된 경우(`PLACE409-ALREADY_DELETED`): "이미 삭제된 장소입니다"

## 4. 복구 (전용 화면 생략)

PRD 결정에 따라 복구 전용 화면은 만들지 않는다. 개발/테스트 단계에서는 placeId를 직접 입력해 `PATCH /admin/places/{placeId}/restore`를 호출하는 임시 입력창으로 대체한다.

- 성공: "복구되었습니다"
- 이미 활성 상태인 경우(`PLACE409-ALREADY_ACTIVE`): "이미 활성 상태인 장소입니다"

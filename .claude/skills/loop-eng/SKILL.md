# 루프 엔지니어링

## 0. 시작 전

- 워크트리에서 작업한다. 워크트리는 `.claude/worktrees/` 아래에 만든다. 다른 세션의 브랜치나 워크트리를 발견하면 먼저 사용자에게 묻는다.
- 새 워크트리에는 gitignore 대상 파일이 없으므로 메인 체크아웃에서 `.env` 계열과 `next-env.d.ts`를 복사하고 `pnpm install`을 먼저 한다.
- 목표 1줄과 체크할 수 있는 완료 조건을 적고 사용자 확인을 받는다.
- 최대 반복 횟수를 정한다 (기본 5).
- 특정 라우트 하나에 국한된 작업이면 `plan-route` 스킬로 `_docs/plan.md`를 먼저 잡는다.

## 1. 루프

1. 가장 작은 단위로 변경한다.
2. 검증한다 (빠른 것부터).
   - `pnpm exec tsc --noEmit`
   - `pnpm test`
   - `pnpm build` (종료 직전). 같은 워크트리에서 dev 서버가 돌고 있으면 `.next`를 덮어써 dev 런타임이 깨지므로 돌리기 전에 확인한다.
   - UI를 바꿨으면 사용자가 띄워둔 dev 서버에서 해당 페이지를 브라우저로 확인한다 (스크린샷). `pnpm dev`는 직접 실행하지 않는다.
3. 실패하면 에러 원문을 읽고, 원인 하나만 고친 뒤 2로 간다.
4. 통과하면 완료 조건과 대조한다. 남은 게 있으면 1로 간다.

## 2. 멈춤 조건

- 완료 조건을 전부 충족하면 종료한다.
- 같은 에러가 2회 나면 가설을 바꾸고, 3회면 멈추고 보고한다.
- 최대 반복에 도달하면 멈추고 현황을 보고한다.
- 검증 우회 금지: `@ts-ignore`, `@ts-expect-error`, `any`로 덮기, `it.skip`이나 테스트 삭제, 체크 삭제.

## 3. 기록

반복마다 한 줄: `#n 무엇을 바꿨나 → pass / fail(에러 요약)`

## 4. 종료

- 로컬 커밋까지만 한다. 이번 루프에서 직접 건드린 파일만 `git add`한다. `git push`와 `gh pr create`는 사용자가 명시적으로 요청할 때만 한다.
- 브랜치명, 루프 기록, 사용자가 직접 확인할 것을 보고한다.
- PR 본문은 `.github/pull_request_template.md` 형식을 따른다.
